# 设备协议（ESP32 / 树莓派那头要实现的东西）

大脑在这边（Mac 或 RDK），身体在那头（ESP32）。
两边用最笨的 HTTP + JSON 通信，**故意不用 WebSocket、不用二进制协议** ——
板子那头出问题时，用浏览器或 `curl` 就能测。

所有接口都是 `POST`，请求和返回都是 JSON。

---

## 1. `POST /speak` —— 说

```json
{"text": "你好呀", "rate": 175, "pitch": 0}
```

设备收到后播放。**推荐做法是不要用板子自带的 TTS**（音色差），而是：

### 更推荐：`POST /audio` —— 推 PCM 过去

大脑这边用晓晓/晓雨合成，转成 **16kHz / 16bit / 单声道 PCM**，
base64 编码后推给设备，设备只管往 I2S 里灌：

```json
{"pcm": "<base64>", "sr": 16000}
```

返回 `{"ok": true}`。

为什么是 PCM 不是 MP3：ESP32 解 MP3 吃 CPU，而且会引入 100ms 以上的延迟。
16kHz 单声道 1 秒才 32KB，Wi-Fi 完全吃得下。

---

## 2. `POST /listen` —— 听

```json
{"seconds": 20}
```

设备那头做三件事：**本地静音检测 → 攒够一句 → 传回来**。
不要在设备上做识别（ESP32 跑不动），只做"什么时候开始、什么时候结束"。

返回：

```json
{"pcm": "<base64, 16kHz 16bit 单声道>"}
```

大脑这边收到 PCM，丢给 whisper。

> 如果嫌 base64 传输浪费，也可以改成设备直接 POST 一个 `audio/wav` 的二进制体，
> 大脑那头用 `request.body` 读。先用 base64，好调试。

---

## 3. `POST /look` —— 看

```json
{}
```

设备拍照（OV2640 之类），返回：

```json
{"jpeg": "<base64>", "w": 640, "h": 480}
```

大脑这边解码 + 做人脸/姿态判断。**判断放在大脑这边**，因为板子算不动。

---

## 4. `POST /face` —— 表情

```json
{"emotion": "happy"}
```

`emotion` 取值：`idle` / `happy` / `curious` / `sad` / `sleepy` / `listening`。

设备那头把这个映射成圆屏上的眼睛/嘴。**这个接口允许失败** ——
连不上就当没有表情，不影响说话。

---

## 5. `POST /ping` —— 探活

返回 `{"ok": true, "name": "tangyuan-body", "version": "0.1"}`。
大脑启动时先 ping 一次，通不过就直接告诉你"设备没连上"。

---

## 设备那头的最小实现顺序

1. **先做 `/ping` 和 `/face`** —— 不需要音频，十分钟能跑通，先确认网络通。
2. **再做 `/audio`（放音）** —— I2S 功放（MAX98357A）+ 喇叭，能出声就成功一半。
3. **再做 `/listen`（收音）** —— I2S 麦克风（INMP441）或麦克风阵列。
4. **最后做 `/look`** —— 摄像头最容易翻车，放最后。

**顺序很重要**：先让"能出声"这件事成立，你的球就活了；摄像头永远可以后补。

## ESP32 选型备注

| 型号 | 能不能用 | 说明 |
|---|---|---|
| ESP32-S3（N16R8） | ✅ 推荐 | 8MB PSRAM，跑 I2S + 屏幕不吃力 |
| ESP32-S3-Korvo-2 | ✅✅ 最省事 | 官方语音板，双麦 + 功放 + 屏接口，例程现成 |
| ESP32 经典款 | ⚠️ 勉强 | RAM 小，音频缓冲容易爆 |
| ESP32-CAM | ⚠️ 只做摄像头 | 没有音频接口，只能单干 |

**ESP32-S3-Korvo-2 是最省心的选择**：麦克风、功放、喇叭接口、屏幕排线都在一块板上，
乐鑫有现成的语音例程。贵一百来块，但省掉的是你最缺的东西 —— 时间。
